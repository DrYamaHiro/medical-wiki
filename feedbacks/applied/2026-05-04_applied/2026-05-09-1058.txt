重要指摘
1. リンク切れが多数あります（優先度: 高）
npm run build は成功しましたが、Docusaurus がリンク切れを警告しています。設定上、リンク切れは warn なのでビルド失敗にはなっていません。 

代表例:

intro.md のカテゴリ一覧は、./Acute-URI、./Cardiovascular、./Dyslipidemia、./Dermatitis など、大文字混在の旧パスを参照しています。実ディレクトリは 010-acute-uri、090-cardiovascular、120-dyslipidemia、200-dermatitis などの番号付き・小文字系です。 

intro.md のツールリンクも /medical-wiki/drug-reference、./Calculators/adrop を参照しており、現在の 800-Drug-Reference / 810-Calculators 系ルーティングと整合していない可能性があります。 

chads.mdx では ../../Cardiovascular/...、../../Stroke/... を参照しており、ビルドではこれらがリンク切れとして検出されています。 

vaccine-billing.mdx でも ../../Acute-URI/...、../../Health-Check/... のような旧大文字パスが残っています。 

changelog.md の臨床計算ツール表は /medical-wiki/docs/Calculators/... を参照していますが、現行ファイルは 810-Calculators 配下に分かれています。 

影響:
ユーザーがトップページ・変更履歴・関連ページから主要疾患や計算ツールへ移動できない箇所が多く、Wikiとしての導線品質に直接影響します。

推奨対応:
まずリンク切れ一覧を機械的に抽出し、以下の順で修正するのが安全です。

intro.md のカテゴリ一覧

changelog.md の /docs/Calculators/...

810-Calculators/** の関連ページリンク

Drug Reference への /medical-wiki/drug-reference 系リンク

onBrokenLinks: 'throw' への変更検討。ただし既存リンクを直してからが安全です。

j11-influenza-b.mdx から j10-influenza-a#ワクチン へのアンカー参照があり、ビルドでアンカー切れとして検出されています。該当箇所では「インフルエンザA型のワクチンセクション」を参照しています。 

影響:

3. ルート・カテゴリ命名が二重化している可能性があります（優先度: 高）
docs 配下の実ディレクトリは 010-acute-uri、090-cardiovascular、810-Calculators のような番号付きパスですが、リンク本文では Acute-URI、Cardiovascular、Calculators のような旧カテゴリ名が多く使われています。 sidebars.js は docs 全体の自動生成なので、実ファイル配置とリンク表記の不一致がリンク切れとして表面化しています。 

影響:
特に Docusaurus / GitHub Pages / Windows case-insensitive 環境の組み合わせでは、ケース違い・管理パス違いがデプロイ漏れやリンク切れの原因になります。リポジトリ内の作業ルールにも、過去にケース違いでステージ漏れが起きた旨が記録されています。 

推奨対応:
「表示名」と「実ルート」を分け、リンクは Docusaurus が生成する実URLに統一する方針を決めるのがよいです。

4. 001-Undifferentiated/00-diagnostic-hub.mdx だけ id: がありません（優先度: 低〜中）
ほとんどの MDX は front matter に id: を持ちますが、00-diagnostic-hub.mdx には id: がありません。 

影響:
Docusaurus はファイルパス由来で動作できるため即時エラーではありません。ただし、他ページとルーティング・リンク・検索結果表示の一貫性が落ちる可能性があります。

推奨対応:
今後修正する場合は、既存リンク影響を確認したうえで id を追加するか、あえてパス由来運用に統一するかを決めるのがよいです。

5. 画像アップロード機能は公開面の安全性確認が必要です（優先度: 中）
ImageUploader は Cloudinary の CLOUD_NAME と unsigned upload preset 名をフロント側に持ち、ブラウザから直接アップロードします。 

また、非表示・並び順・featured 画像は localStorage に保存されており、サーバー側削除・全ユーザー共通の状態変更ではありません。 

影響:

upload preset が公開アップロード可能な設定だと、第三者による不要画像アップロード・容量消費のリスクがあります。

「非表示」はユーザー端末ローカルの状態であり、全体から消えるわけではありません。

推奨対応:

Cloudinary 側で upload preset の制限を確認してください。

allowed formats

max file size

folder 制限

moderation

unsigned preset の有効/無効

rate limit / abuse 対策

公開Wikiで誰でもアップロード可能にする意図がないなら、管理者限定の署名付きアップロードへ移行するのが安全です。

6. MDXComponents.js のグローバル登録は限定的です（優先度: 低）
グローバル MDX コンポーネントとして登録されているのは、ImageUploader、DiagnosticBooster、TreatmentBooster、MermaidChart、DupixentCalculator などに限られています。 

一方、各 Calculator ページは個別にコンポーネントを import しているため、現時点でビルドは成立しています。例として EASI は MDX 内で EasiCalculator を直接 import しています。 

影響:
大きな問題ではありませんが、計算ツール群をグローバル登録する方針なのか、各MDXで明示 import する方針なのかが混在して見えます。

推奨対応:
明示 import 方針に統一するなら DupixentCalculator のみグローバル登録されている理由を整理すると保守しやすくなります。

良い点
